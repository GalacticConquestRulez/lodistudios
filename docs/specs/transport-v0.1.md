# Transport v0.1 — the libssh2 core, in the order it should be proven

Read docs/plan.md "Libraries" and "The security control that matters most" first. This is the
build order for the `SSHTransport` seam that already exists in LodiKit. Prove each milestone
against the real Sessions droplet before starting the next; every milestone is a commit.

## Hosts to test against (docs/hosts.md has the fingerprints)
- **Sessions** `67.205.136.45` (root) — the app's own box. Use this for everything.
- **greenflash** `142.93.198.162` — only for the onward-hop test at the end; it serves clients.

## Milestone 0 — libssh2 as an xcframework
`scripts/build-libssh2.sh`: current libssh2 (1.11.x) with the **mbedTLS** crypto backend (small,
builds cleanly for iOS via CMake; OpenSSL is the alternative if mbedTLS fights back), for
macOS arm64, iOS arm64 and iOS Simulator arm64, packaged with `xcodebuild -create-xcframework`.
Vendor the built xcframework in the repo under `Vendor/` so a clone builds without the script;
keep the script so it can be rebuilt. Expose it to Swift through a C module (`CLibSSH2`).

## Milestone 1 — connect and run one command
`SSHSession` (an actor) owning one `LIBSSH2_SESSION` in **non-blocking mode** from the first
call (`libssh2_session_set_blocking(s, 0)`; drive with `libssh2_session_block_directions()`
and a socket wait — issue #535 is why). Handshake → host key check against a known-hosts store
(pin by fingerprint; refuse on mismatch; first-connect prompt via a Command so the Assistant can
answer it) → `libssh2_userauth_publickey()` with a **sign callback** that calls
`SecKeyCreateSignature` on a Keychain-held ed25519 key generated by the app on first launch.
The app shows the public key; the owner (or the droplet session) adds it to Sessions'
`authorized_keys`. Prove: `exec("uname -a")` returns Sessions' kernel string. Commit.

## Milestone 2 — the app is its own agent
A Unix-domain socket inside the app container speaking the OpenSSH agent protocol:
`REQUEST_IDENTITIES`, `SIGN_REQUEST` (same SecKey path), and accept
`session-bind@openssh.com` extensions (record them; enforcement is v0.4). Point libssh2 at it
with `libssh2_agent_set_identity_path()` and authenticate via the agent instead of the
callback. Then `libssh2_channel_request_auth_agent()` on a shell channel and prove forwarding:
from a shell on Sessions, `ssh-add -l` lists the phone's key. Commit.

## Milestone 3 — a terminal you can type into
Channel with PTY (`xterm-256color`, real size) running `tmux new -A -s <name>`. Channel reads →
`PaneOutputBroadcaster`; a `PaneBackend` writing to the channel behind `PaneWriter`; window
resize → `libssh2_channel_request_pty_size`. SwiftTerm's `TerminalView` (AppKit and UIKit) as
one sink. Prove: `cc -l` output renders, keys echo, `htop` draws correctly. Commit.

## Milestone 4 — disconnect is not an event
Drop the network (Wi-Fi off): the transport reports `.disconnected(reason:)`, the tab shows a
reconnect banner that says why, and on network return it reconnects and re-runs the same
`tmux new -A -s <name>` — scrollback comes back from tmux, never from the app's memory.
Detect a tmux server restart (session gone) and say so rather than showing an empty pane. Commit.

## Milestone 5 — Secure Enclave
Generate a `kSecAttrTokenIDSecureEnclave` EC key; present as `ecdsa-sha2-nistp256` through the
same sign callback / agent. Prove the round trip against Sessions. If it fights back, the
Keychain ed25519 key stays as the fallback and this becomes a v0.4 item — say so, don't stall.

## Milestone 6 — onward hop (last)
From a Sessions shell, `ssh greenflash` using the forwarded agent. Then the onward test the
whole security design exists for: the agent logs the `session-bind` it received. Commit.

## Not in this spec
SFTP (v0.2, `libssh2_sftp_*` over the same session), tmux control mode (v0.3), Mosh, the
location keep-alive, destination-constraint enforcement (v0.4).

## Rules that apply throughout
- Every user-facing action (connect, disconnect, reconnect, accept host key, copy public key)
  is a Command in the registry. No bare actions.
- Terminal chrome carries the tool accent; scrollback is never branded.
- Keys never leave the device; the private key is never readable by Swift code — only signed with.
