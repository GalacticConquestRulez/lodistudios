# Review — v0.1 shell, commits 1b2211e and 1522c51

Reviewed from the droplet session against docs/plan.md and docs/ui-review.md. Verdict: **a
strong skeleton — keep going.** The registry, the pane seams and the theme are exactly what the
plan asked for. Four things to do before the next feature, in order; the first is on me.

## 1. `SSHConfigRenderer` — a stale spec, my error, not yours
The v0.1 bullet in docs/plan.md still described the withdrawn subprocess design (ssh_config,
ControlMaster, `ssh -t … tmux`). It is corrected in this push. What to do with the code:
- Keep `Host` / `HostInventory` — they are the inventory the plan wants.
- Remove `ControlMaster` / `ControlPath` / `ControlPersist` / `IdentityAgent` from
  `SSHConfigOptions`: they are OpenSSH-client concepts and nothing in the app runs OpenSSH.
- Keep the renderer only as an **export** (`SSHConfigExport`) for the Mac's own Terminal and
  git — a small user feature — and make sure nothing in LodiKit consumes its output. The
  golden-file test stays, retargeted.

## 2. Navigation must go through the registry
`nav.board` and `nav.<tool>` are registered but their bodies are empty, and `RootView` owns
`selection` privately — so today the Assistant and ⌘K could not switch screens, which is the
first thing they must do. Add an `@Observable Navigator` in LodiKit (current destination, plus
`go(to:)`), inject it like the registry, bind `RootView`'s selection to it, and make the nav
commands call `navigator.go`. Then `registry.run("nav.webPro")` changes the screen. Same for
`assistant.toggle` once the panel exists.

## 3. Put `CLAUDE.md` beside the `.xcodeproj`
The project sits at `LodiStudios/LodiStudios/LodiStudios.xcodeproj`, so Xcode's agent does not
see the repo's `CLAUDE.md`. Cheapest fix, no divergence: a symlink —
`ln -s ../../CLAUDE.md LodiStudios/LodiStudios/CLAUDE.md` — committed. (Moving the project to
the repo root is also fine if you prefer; either way, one file governs both agents.)

## 4. Next feature: ⌘K and the Assistant panel
Both were in the first prompt and neither is in this push — expected for a first commit, and
they are the next two things. ⌘K reads `registry.search`; the Assistant panel is docked right,
carries `lodiAssistant()` and nothing else does, and its first three abilities are navigate,
invoke a command, and log a request to `docs/requests.md`-shaped storage.

## What is right and should not change
- `CommandRegistry`: main-actor, one `run` door, availability, ranked search, parameter check,
  duplicate-id precondition. This is the spine; nothing bypasses it.
- `PaneOutputBroadcaster` (weak sinks) and `PaneWriter` with a policy in front, present before
  any terminal output exists. Exactly the week-one rule.
- `SSHTransport` seam plus `FakeSSHTransport`, so UI can be built before the C core.
- `LodiTheme`: palette from the logo, pink reserved for the Assistant with the rule in the
  comment, per-tool accent through the environment, `lodiTool()` / `lodiAssistant()`, no hex in
  views. LodiAdmin white by design. Textbook.
- No bare actions anywhere in the views. Keep it that way; it will be checked every push.
