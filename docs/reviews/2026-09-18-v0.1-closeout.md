# Review — 276acd5, v0.1 close-out: SSH-backed HostFacts

**Verdict: right shape.** One connection, one exec (`df -P /; free -m; uptime` with `###`
markers), pure parsers with tests fed by real droplet output, an honest "unreachable" fact on
failure instead of a throw, ProxyJump hosts falling back to the fake provider until onward-hop
facts exist. Thresholds are sensible (disk 80/90, swap warns above 25%).

## To finish the step
1. **It isn't wired in yet.** The app still gets `FakeHostFactsProvider` through the
   environment default. Inject `SSHHostFactsProvider(agentSocketPath:)` at the app root.
2. **One agent per app, not per host.** The provider needs an agent socket, and `TerminalStore`
   currently starts an agent per host. Start a single `SSHAgent` at launch, hand its socket path
   to both the terminal store and the facts provider. Same key, same responder; nothing else changes.
3. **Refresh.** `BoardView` loads facts once per host list. Re-run on a timer (60 s is fine) and
   on app foreground, showing "as of HH:MM" beside the card so a stale number is never mistaken
   for a live one.
4. **The facts the review actually asked for** — git ahead/behind and uncommitted changes on
   the site trees, systemd timers with last result, cert expiry, DNS → this box — are per-role
   and land with WebPro/Admin. Keep this provider generic; add a second script per role later.

greenflash is directly reachable from the Mac (it authorises the Enclave key, ECDSA host key
pinned), so both hosts will show real vitals the moment item 1 is done. The fake data's three
famous facts (21 unpushed commits, the foreign DNS, the swap) become real numbers — and the
swap one will be true.

# a91f4aa — wired in, refreshing every 15 s

Wired: the app injects `SSHHostFactsProvider` at the root with a Board-owned agent, and the
Board loops, filling each host as its facts return. Real vitals on the Board — item 1 done.

**Two changes before this runs all day:**
1. **15 s is too chatty as implemented.** Each refresh opens a *new SSH connection per host* —
   handshake, key exchange, a login line in the journal — so two hosts at 15 s is nearly six
   thousand logins a day per droplet, and measurable CPU on a 2-vCPU box. Either refresh at
   **60 s** (fine for vitals) or, better, keep **one persistent session per host** for facts
   (the M3 session machinery already exists) and exec the script over it. Do the 60 s now; the
   persistent session can come with the per-role facts.
2. **Show "as of HH:MM:SS"** on each host card, so a stale number is never mistaken for a live one.

**Accepted, with a note:** a separate Board agent rather than one app-wide agent (item 2 of the
previous note). Same key, same responder, no security difference — just one more socket and
thread. Fine for now; consolidate when the agent grows destination-constraint state (v0.4),
because that state must not be split across agents.

**One more, and it matters:** greenflash is inventoried with a `proxyJump`, so the provider
falls back — to the **fake** provider, which shows invented facts ("21 commits unpushed",
"hewanorra.com → foreign IP") on a real host card. In production a fallback must be honest:
replace it with a single fact, `Reachability: via jump — facts not yet available`, status
unknown. And note greenflash *is* directly reachable from the Mac (public IP, Enclave key
authorised, ECDSA host key pinned) — the jump is for Sessions → greenflash, not Mac → greenflash.
Either drop the `proxyJump` for the Board's direct probe, or teach the provider that the jump
only applies from Sessions. greenflash's log shows zero Board logins, which is this.
